# 🧠 What Is a Composite Action?

A composite action is:

> A reusable bundle of steps defined in an `action.yaml` file.

It allows you to:

* Package step sequences
* Define inputs
* Define outputs
* Reuse logic across workflows or jobs

It runs directly in the runner environment.

No Docker required.
No Node required.

Just YAML + shell.

![](Images\composite-action.png)

---

# 📂 How to Create One

Create a file named:

```
action.yaml
```

Example:

```yaml
name: 'Hello World'
description: 'Greet someone'

inputs:
  who-to-greet:
    description: 'Who to greet'
    required: true
    default: 'World'

runs:
  using: 'composite'
  steps:
    - name: Set Greeting
      run: echo "Hello $INPUT_WHO_TO_GREET."
      shell: bash
      env:
        INPUT_WHO_TO_GREET: ${{ inputs.who-to-greet }}
```

# 🔎 Anatomy Breakdown

## 1️⃣ Metadata

```yaml
name:
description:
```

Describes the action.

---

## 2️⃣ Inputs

```yaml
inputs:
```

Defines parameters consumers can pass.

Access via:

```yaml
${{ inputs.input-name }}
```

---

## 3️⃣ runs: composite

```yaml
runs:
  using: 'composite'
```

Tells GitHub:

This action executes step sequences directly.

---

## 4️⃣ Steps

Same syntax as workflow steps.

You can:

* Run bash
* Call other actions
* Set environment variables

# 🧠 Important: You Must Checkout

When consuming a local composite action, the runner must have the repository code.

Therefore:

```yaml
- uses: actions/checkout@<commit-sha>
```

is required before referencing:

```yaml
- uses: ./path-to-action
```

Without checkout, the action.yaml file won’t exist on the runner.

---

# 📦 Consuming the Composite Action

Example workflow:

```yaml
jobs:
  hello-world:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@ff7abcd0c3c05ccf6adc123a8cd1fd4fb30fb493 # v5.0.0

      - id: composite-action-instance
        uses: ./06-authoring-actions/composite-action
        with:
          who-to-greet: "from composite action in hello-world-1!"
```

Key points:

* `uses: ./relative-path`
* Inputs passed under `with:`

# 📂 Recommended Directory Convention

In real projects:

Store custom actions under:

```
.github/actions/<action-name>/action.yaml
```

This makes it:

* Discoverable
* Organized
* Clear to contributors

---

# ⚖️ When to Use Composite Actions

Use when:

* You want to share step sequences
* You need lightweight reuse
* You are wrapping shell logic

Do NOT use when:

* You need heavy logic
* You need compiled code
* You need custom runtime environments

In those cases, use:

* JavaScript action
* Container action
