# 4.2 — Persisting Build Outputs with Artifacts

**Source:** DevOps Directive — GitHub Actions

**Module:** 4 (Advanced Features)

**Date:** 16/02/2026

---

# 🎯 Core Problem

GitHub Actions runners are **ephemeral**.

That means:

* A fresh virtual machine (or container) is created for each job.
* Everything created during the job exists only for the lifetime of that runner.
* When the job finishes → the runner is destroyed.
* All files disappear.

So if you:

* Build a binary
* Generate a test report
* Produce a compiled artifact
* Create logs

They are gone after the job ends.

---

# 🧠 What Are Artifacts?

Artifacts are a way to:

> Persist files outside the lifecycle of an ephemeral runner.

They are stored in GitHub’s object storage and attached to the workflow run.

Artifacts allow you to:

* Share files between jobs
* Download build outputs later
* Preserve logs and test results
* Debug historical runs

# 🔁 Producer → Consumer Pattern

Artifacts are commonly used in a two‑job pattern:

1️⃣ Producer job creates files and uploads them.

2️⃣ Consumer job downloads and uses them.

---

# Example Workflow

```yaml
jobs:
  artifact-producer:
    name: Produce artifact
    runs-on: ubuntu-24.04
    steps:
      - name: Create artifact file
        run: |
          echo "This will be stored as an artifact!" > artifact.txt
          echo "Generated by artifact-producer job on $(date)" >> artifact.txt

      - name: Upload artifact
        uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02
        with:
          name: example-artifact
          path: artifact.txt

  artifact-consumer:
    name: Consume artifact
    runs-on: ubuntu-24.04
    needs: artifact-producer
    steps:
      - name: Download artifact
        uses: actions/download-artifact@634f93cb2916e3fdff6788551b99b062d0335ce0
        with:
          name: example-artifact

      - name: Cat artifact file
        run: cat artifact.txt
```

---

# 🔍 Step-by-Step Breakdown

## 1️⃣ Create the File

Inside the producer job:

```bash
echo "This will be stored as an artifact!" > artifact.txt
```

This file exists only inside the runner at this moment.

---

## 2️⃣ Upload Artifact

```yaml
uses: actions/upload-artifact@<pinned-commit>
```

Key inputs:

* `name:` logical name of artifact
* `path:` file or directory to upload

This stores the file in GitHub storage and associates it with the workflow run.

⚠ Note the commit SHA is pinned. This prevents supply chain risks.

---

## 3️⃣ Declare Dependency

```yaml
needs: artifact-producer
```

This ensures:

* Producer completes first
* Artifact exists before download

---

## 4️⃣ Download Artifact

```yaml
uses: actions/download-artifact@<pinned-commit>
```

GitHub:

* Fetches artifact from storage
* Extracts it into the working directory

Now the consumer job can access it normally.

---

# 🖥 What You See in the UI

After a workflow run completes:

* Artifacts appear in the run summary
* They are downloadable as ZIP files
* Each artifact is tied to a specific run

This allows historical inspection.

---

# 🧠 Critical Mental Model

Environment variables:

* Persist only within a job

Artifacts:

* Persist beyond job lifetime
* Can cross job boundaries
* Can be downloaded days later

Artifacts are not for small values like strings.
They are for files.

---

# 📦 Common Real-World Use Cases

* Build binaries (Go, Java, Node, etc.)
* Store compiled frontend bundles
* Upload test coverage reports
* Persist Docker build metadata
* Preserve logs for debugging

---

# 🚨 Important Characteristics

* Stored per workflow run
* Automatically zipped
* Retained for a configurable period
* Not meant for long-term storage like S3

---

# 🧠 Why This Matters for DevOps Lock‑In

Artifacts introduce the idea of:

> Decoupling compute from storage.

Runners are disposable.
Artifacts are persistent.

This mirrors cloud architecture principles:

* Stateless compute
* Persistent object storage

---

# 🔑 Final Takeaways

* Runners are ephemeral.
* Artifacts persist files beyond job lifetime.
* Use upload/download actions.
* Gate downstream jobs with `needs:`.
* Artifacts appear in UI and are downloadable.

Artifacts are the bridge between ephemeral execution and persistent outputs.
