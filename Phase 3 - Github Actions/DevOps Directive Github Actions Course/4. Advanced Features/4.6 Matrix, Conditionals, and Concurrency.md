# 1️⃣ Matrix Strategy — Parallel Job Expansion

## 🧠 What Is a Matrix?

A matrix allows you to run the **same job multiple times with different inputs**.

Instead of copying a job 6 times, you define combinations and GitHub generates them.

---

## 🔹 Example

```yaml
strategy:
  fail-fast: true
  matrix:
    number: [1, 2]
    letter: [a, b, c]
    exclude:
      - number: 1
        letter: c
```

### What GitHub Does

Without exclude:

1a
1b
1c
2a
2b
2c

6 combinations.

With exclude (1c removed):

1a
1b
2a
2b
2c

5 jobs run in parallel.

---

## 🔹 Accessing Matrix Values

Inside steps:

```yaml
${{ matrix.number }}
${{ matrix.letter }}
```

Each job instance receives its own matrix context.

---

## 🔹 fail-fast

```yaml
fail-fast: true
```

If one matrix job fails:

* Remaining matrix jobs are cancelled.

Useful for test pipelines.

# 2️⃣ Conditionals — Smart Execution

Conditionals allow you to run steps or jobs only when specific logic evaluates to true.

Syntax:

```yaml
if: <expression>
```

---

## 🔹 Matrix-Based Conditional

```yaml
if: ${{ ! (matrix.number == 2 && matrix.letter == 'c') }}
```

This means:

"Run this step for all combinations EXCEPT 2c"

Result:

* Step skipped only for 2c
* Job still runs

---

## 🔹 Conditional Context Examples

You can reference:

* matrix
* github
* needs
* steps
* env

Example:

```yaml
if: ${{ github.ref == 'refs/heads/main' }}
```

Only runs on main branch.

# 3️⃣ Concurrency — Avoid Wasted Compute

When you push multiple commits quickly:

You may have multiple workflow runs executing simultaneously.

Often, older runs are useless once a new commit exists.

Concurrency lets you cancel outdated runs automatically.

---

## 🔹 Concurrency Example

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

### What This Means

Group runs by:

* Workflow name
* Git branch

If a new run starts for the same group:

→ Previous run is automatically cancelled.

---

## 🔹 Why This Is Powerful

Without concurrency:

Push 5 commits → 5 full CI runs → wasted time + money

With concurrency:

Push 5 commits → only latest run continues

This is critical for:

* Large monorepos
* Expensive integration tests
* Docker builds

---

# 💤 Example Sleep Job (To Demonstrate Cancellation)

```yaml
sleep-job:
  runs-on: ubuntu-24.04
  steps:
    - name: Sleep
      run: sleep 100
      timeout-minutes: 2
```

Purpose:

* Keep workflow alive long enough
* Trigger another run
* Observe cancellation in action
