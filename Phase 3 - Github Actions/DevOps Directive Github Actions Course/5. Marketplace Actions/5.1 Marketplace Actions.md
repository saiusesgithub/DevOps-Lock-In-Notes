# 🧱 What Is an Action?

A step in a workflow can be:

* Inline bash
* Inline Python
* OR an **Action**

An Action is:

> A reusable application packaged in a GitHub repository that runs as a step inside your workflow.

When you write:

```yaml
- uses: actions/checkout@<ref>
```

You are executing code from another repository.

This makes Actions **dependencies** in your CI/CD system.

# 🌍 The GitHub Marketplace

URL:

```
https://github.com/marketplace?type=actions
```

The Marketplace is:

* A discovery layer
* A searchable catalog
* A list of repositories that publish actions

You can:

* Search by tool (e.g., Cypress)
* Filter by category
* View source repository
* Inspect documentation

There are thousands of actions available.

# 🔎 How to Evaluate an Action

Actions execute with your workflow’s permissions and secrets.

That means:

⚠️ They are part of your supply chain.

You must evaluate them like any open-source dependency.

---

## 1️⃣ Does It Solve Your Problem?

Ask:

* Is this better than writing a simple bash script?
* Does it provide meaningful abstraction?
* Does it save time?

Use actions that add real value.

---

## 2️⃣ Is the Publisher Trustworthy?

Look for:

* 🔵 Blue “Verified” badge (GitHub-verified identity)
* Official organization (e.g., GitHub, Docker, AWS)

Verified does NOT mean perfect — but it’s a strong signal.

---

## 3️⃣ Is the Project Healthy?

Check:

* ⭐ Star count
* 🕒 Recent commits
* 🐛 Active issue responses
* 📦 Recent releases

Red flags:

* No commits in years
* Unanswered issues
* Sparse documentation

# 🔐 Pin Actions by Commit SHA (CRITICAL)

When using an action, you can reference:

❌ Dangerous:

```yaml
- uses: actions/checkout
- uses: actions/checkout@v5
- uses: actions/checkout@v5.0.0
```

These rely on mutable tags.

Tags can be moved.

In 2025, a compromised action retagged releases to inject malicious code.

---

✅ Secure:

```yaml
- uses: actions/checkout@ff7abcd0c3c05ccf6adc123a8cd1fd4fb30fb493 # v5.0.0
```

Why this is secure:

* Commit hashes are immutable
* Cannot be altered retroactively
* Guarantees reproducibility

Always add a comment with the human-readable version.

Marketplace Actions are:

> Executable dependencies inside your CI/CD pipeline.

Treat them like:

Supply-chain security applies.

---

# 📦 Popular Official Actions

### Core GitHub Actions

* `actions/checkout` → Clone repository
* `actions/cache` → Cache dependencies
* `actions/upload-artifact`
* `actions/download-artifact`
* `actions/github-script` → Execute GitHub API logic via JS

These are used in nearly every serious repository.

---

# ⚙️ Runtime Installers (Very Common)

* `actions/setup-node`
* `actions/setup-go`
* `actions/setup-java`

These:

* Install specific language versions
* Configure environment
* Integrate caching

Used in most CI workflows.

---

# ☁️ Authentication Helpers

For cloud integration:

* `aws-actions/configure-aws-credentials`
* `azure/login`
* `google-github-actions/auth`

They abstract:

* Credential acquisition
* OIDC flows
* CLI configuration

Without these, you’d write complex scripts manually.

---

# 🐳 Container & DevOps Utilities

* `docker/build-push-action` → Build & push multi-arch images
* `github/super-linter` → Multi-language linting

These are production-grade building blocks.

---

# 🧠 Decision Framework

When selecting an action:

1. Does it add real value?
2. Is it maintained?
3. Is it secure?
4. Can I pin it safely?
5. Would writing this myself be simpler?

If unsure:

* Fork it
* Audit it
* Or implement the logic manually
