## 1. Installation Philosophy

For this lock‑in phase:

* Prefer **manual and explicit installation**
* Avoid magic installers or abstractions
* Know exactly **where Terraform lives** and **how it is invoked**

Terraform should feel like a **tool you control**, not something that mysteriously works.

## 2. Installing Terraform on Windows

### Step 1: Download Terraform

* Visit: [https://developer.hashicorp.com/terraform/downloads](https://developer.hashicorp.com/terraform/downloads)
* Choose:

  * **Windows**
  * **AMD64**
  * Version used: **1.14.4**

Important clarification:

* **AMD64 does NOT mean AMD CPU**
* It refers to the x86_64 architecture
* Intel i5‑1335U fully supports AMD64

---

### Step 2: Extract the Binary

* Extract the downloaded ZIP
* You will get a single file:

  terraform.exe

---

### Step 3: Place Terraform Binary

Create a folder:

C:\terraform

Move the binary:

terraform.exe → C:\terraform\

---

### Step 4: Add Terraform to PATH

1. Search **Environment Variables**
2. Open **Edit the system environment variables**
3. Click **Environment Variables**
4. Under **System variables**, edit `Path`
5. Add:

C:\terraform

6. Save and close
7. Restart your terminal

---

### Step 5: Verify Installation

Run:

terraform -version

Expected result:

* Terraform version displayed
* OS and architecture shown

## 3. AWS Authentication Setup

Terraform does **not** manage credentials directly.
It relies on the cloud provider’s authentication system.

For AWS, this means **AWS CLI credentials**.

---

### Step 1: Create IAM User and Group

A dedicated IAM user was created specifically for Terraform.

IAM Group permissions used in the course:

* AmazonEC2FullAccess
* AmazonRDSFullAccess
* AmazonS3FullAccess
* AmazonDynamoDBFullAccess
* AmazonRoute53FullAccess
* IAMFullAccess

Note:

* These permissions are intentionally broad
* Used **only for learning**, not production

---

### Step 2: Install AWS CLI

Install from:
[https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)

Verify:

aws --version

---

### Step 3: Configure AWS Credentials

Run:

aws configure

Provide:

* Access Key ID
* Secret Access Key
* Default region (example: us‑east‑1)
* Output format: json

This creates a credentials file at:

~/.aws/credentials

Terraform automatically uses these credentials when the AWS provider is configured.

## 4. First Terraform Configuration (Hello World)

File name:

main.tf

Contents:

```
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 3.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "example" {
  ami           = "ami-011899242bb902164" # Ubuntu 20.04 LTS // us-east-1
  instance_type = "t3.micro"
}
```

Notes:

* `t3.micro` was used instead of `t2.micro` because it is free‑tier eligible
* This is the **minimal valid Terraform configuration**

## 5. First Terraform Lifecycle (Observed, Not Memorized)

### Step 1: Initialize

Command:
```
terraform init
```
What happens conceptually:

* Initializes the working directory
* Downloads required providers
* Sets up backend and state (local by default)

---

### Step 2: Plan

Command:

```
terraform plan
```
What Terraform does:

* Queries AWS API
* Compares desired configuration with real infrastructure
* Displays proposed changes
* Makes **no actual changes**

Purpose:

* Reduce fear
* Increase predictability

---

### Step 3: Apply

Command:
```
terraform apply
```
What happens:

* Executes planned actions
* Provisions EC2 instance
* Updates Terraform state

Observations:

* Some values are only known after apply
* Terraform is explicit and conservative

---

### Step 4: Destroy (Cleanup)

Command:
```
terraform destroy
```
Purpose:

* Clean up resources
* Avoid unnecessary costs
* Reinforce disposable infrastructure mindset

Destroy is part of the normal lifecycle, not a failure.

---

## 6. Key Observations from First Task

* Terraform always checks current state before acting
* Configuration is not reality until applied
* State updates only after successful execution
* Terraform is **diff‑driven**, not command‑driven
