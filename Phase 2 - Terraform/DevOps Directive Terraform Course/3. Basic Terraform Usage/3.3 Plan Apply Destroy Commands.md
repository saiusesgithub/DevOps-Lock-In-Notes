# Terraform Plan, Apply, Destroy — Execution Semantics

> **Course:** DevOps Directive — Terraform: Beginner to Pro

> **Section:** Part 3.3 (Execution Commands)

> **Goal:** Understand how Terraform reconciles desired state with actual state and why plan/apply/destroy exist as separate, intentional steps.

> **Date:** 01/02/2026

---

## 1. The Core Idea Behind These Commands

Terraform is a **state reconciliation engine**.

At all times, Terraform reasons about two things:

* **Desired state** → what your configuration files declare
* **Actual state** → what Terraform believes exists (from the state file)

The commands `plan`, `apply`, and `destroy` are simply **different ways of interacting with this reconciliation process**.

---

## 2. Terraform Plan — Thinking Before Acting

### What `terraform plan` Does

* Reads Terraform configuration (desired state)
* Reads Terraform state file (last known actual state)
* Compares the two
* Calculates the exact set of changes required

No infrastructure is modified during this step.

---

### How Terraform Reasons During Plan

Conceptually:

* If config == state → no changes
* If config > state → create resources
* If config < state → destroy resources
* If config != state → update or replace resources

Example from the transcript:

* Desired: 4 servers
* Actual: 3 servers
* Plan result: add 1 server

---

### Why `plan` Exists

`plan` exists to:

* Reduce fear
* Prevent accidental destruction
* Make infrastructure changes reviewable
* Enable approval workflows

In real teams:

* Plans are reviewed in pull requests
* Humans approve before apply

`plan` is Terraform’s **safety layer**.

---

## 3. Terraform Apply — Making Reality Match Desire

### What `terraform apply` Does

* Takes the planned changes
* Executes the required provider API calls
* Creates, updates, or deletes resources
* Updates the Terraform state file after success

This is the **only step that changes real infrastructure**.

---

### Important Characteristics of Apply

* Terraform executes changes in dependency order
* Some values are only known after apply
* If apply fails midway:

  * Partial state may exist
  * Terraform relies on state to recover

Apply is intentionally:

* Explicit
* Confirmed
* Conservative

---

## 4. Terraform Destroy — Intentional Deletion

### What `terraform destroy` Does

* Reconciles desired state to **nothing**
* Deletes all resources tracked in state
* Updates state to reflect destruction

Destroy is not a special case — it is just another reconciliation.

---

### When Destroy Should Be Used

Appropriate use cases:

* Cleaning up learning environments
* Tearing down demo or test infrastructure
* Decommissioning projects

Not appropriate:

* Active production systems
* Live environments still in use

Destroy is powerful and irreversible.

---

## 5. Drift and Why Terraform Cares

Terraform assumes:

* All infrastructure changes happen through Terraform

If changes are made manually (GUI / CLI):

* State becomes inaccurate
* Terraform’s decisions may become dangerous

This is called **infrastructure drift**.

Best practice:

* Avoid out-of-band changes
* If unavoidable, reconcile carefully

---

## 6. Mental Model to Lock In

* Config files = desired future
* State file = remembered past
* Plan = diff computation
* Apply = execution of diff
* Destroy = diff to zero

Terraform is not running commands.
It is **moving reality toward a declared truth**.
